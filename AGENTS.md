# AGENTS.md

Instructions for AI coding agents (Claude Code, Copilot, Cursor, Codex…) and humans working in this repo. Read this
first, then [MEMORY.md](MEMORY.md) (status, decisions, verified facts), [CONNECTIONS.md](CONNECTIONS.md) (wiring and
contracts) and [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) (remaining work).

## Project in one paragraph
TerraPulse AI is the GeoAI Hackathon (IIT Bombay CSRE) entry. It answers free-form questions such as "I have mild
asthma, where's good for a morning walk near ‹area› in the next two days?" with the best nearby **place × time**, plus
what to carry, what to watch for and when to avoid going. A ≤3B open SLM (Qwen3-1.7B + LoRA, GGUF via llama.cpp) parses
the question and writes the answer. A deterministic engine fetches **live** open data, scores venues × hours with
three-valued safety rules, and builds an evidence ledger. A verifier rejects any answer whose facts aren't in the
ledger. Deadline: **24 Oct 2026, 23:59 IST**.

## Non-negotiable rules (breaking these can disqualify the team)
1. **Never fabricate data.** No synthetic venues, simulated weather, baseline AQI, default coordinates/cities, canned
   answers, or frontend demo responses. If a source fails, mark it unavailable and say so. `tests/test_no_hardcoding.py`
   enforces part of this, so keep it green.
2. **No knowledge in code.** Thresholds, OSM tags, synonyms, profiles, rules, advice, time words, scoring curves and
   verifier vocabulary belong in `backend/app/knowledge/*.yaml`, each with a source comment. Place names may appear
   only in `training/` generators, never in `backend/app/`.
3. **Every user-facing number, time and place comes from the evidence ledger** and must pass
   `evidence/grounding.py`. New facts → add an `Evidence` record in `evidence/factsheet.py`.
4. **Runtime model ≤3B, open weights, self-hosted.** `Qwen/Qwen3-1.7B` (bake-off winner). Never Phi-3/Phi-4-mini
   (3.8B), Ministral-3-3B (3.85B), Granite-micro (3.4B), Llama-3.2-3B (3.21B), Qwen2.5-3B (non-open licence). No hosted
   LLM APIs anywhere in the app, and none for training data (the teacher is open Qwen3-8B).
5. **Training runs only in Google Colab** (VS Code Colab extension, T4), never on the developer's machine. Notebooks
   are generated by `training/make_notebooks.py`: edit that file, then regenerate.
6. **Free, open data only**, disclosed in README and the API `sources`. All HTTP goes through
   `data_services/http.py` (`HttpGateway`: per-host rate limits, backoff). Nominatim needs the contact User-Agent.
7. **Ask, don't guess.** Missing location or activity → `clarification_needed`; ambiguous place → ask with options;
   missing time → assume the next ~36 h and say so.
8. **Time is timezone-aware** (`APP_TZ`, default Asia/Kolkata). Never `date.today()` / `datetime.utcnow()`.
9. Profiles may only **tighten** limits (`Knowledge.effective_limits`).
10. Credit "© OpenStreetMap contributors" wherever map data is shown.

## Pipeline stages (`backend/app/agent/pipeline.py`)
| Stage | Module | Notes |
|---|---|---|
| Understand | `agent/understand.py`, `slm/runtime.py`, `slm/prompts.py`, `schemas/intent.py` | SLM JSON (grammar) ∪ rule parser (`agent/rule_parser.py`), profiles unioned |
| Time | `agent/time_resolver.py` | resolves on the full question; sunrise/sunset anchors filled from live data |
| Clarify/scope | inside `pipeline.run` | early `final` events |
| Locate | `data_services/geocoding_service.py` | settlement-type ranking, true ties → ask |
| Venues | `data_services/osm_service.py` (Overpass rolling race + circuit breaker) → `Pipeline._nominatim_candidates` fallback | `Pipeline._select` filters/dedupes |
| Live data | `weather_service.py`, `air_quality_service.py` (+WAQI), `routing_service.py`, `osm_service.fetch_context` | multi-coordinate single calls |
| Analyse | `geospatial/context.py`, `geospatial/exposure.py` | shapely, local metric projection |
| Score | `scoring/grid.py`, `scoring/rules_engine.py` | venue × hour, 3-valued rules, windows, contrast |
| Advise | `advice/rules.py` | `knowledge/advice.yaml` |
| Fact sheet | `evidence/factsheet.py`, `evidence/ledger.py` | E-ids, URLs, methods |
| Compose/verify | `slm/runtime.py`, `evidence/grounding.py`, `advice/template.py` | repair once, then template |

## Commands
```bash
# backend
cd backend && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
pytest -q                                          # offline; must stay green
SLM_LOCAL_PATH=/path/to/model.gguf uvicorn app.main:app --port 8000   # or let it download from HF
python -m eval.run_eval --base http://localhost:8000          # live eval (paced; hits real APIs)
python -m eval.bakeoff a.gguf b.gguf --compose                # model comparison (inference only)

# frontend
cd frontend && npm install && npm run dev          # :5173, proxies /api → :8000
npm run build                                      # FastAPI serves dist/ at /

# training (Colab only): regenerate notebooks after editing make_notebooks.py
python training/make_notebooks.py
```

## Conventions
- Python 3.11+, FastAPI, Pydantic v2 for API/intent schemas, `@dataclass` for internal results, async httpx through
  `HttpGateway`, `logging.getLogger(__name__)`, type hints on public functions, short docstrings; comments only for
  formulas, thresholds and non-obvious choices.
- Tests in `backend/tests/`, network mocked with `respx`; fixtures must be obviously fictional (e.g. "Testville").
- Frontend: React 19 + TypeScript, API calls only in `src/services/api.ts`, types in `src/types/index.ts`, CSS tokens in
  `src/index.css` (dark + light).
- Don't commit model weights, `.cache/`, `.env`, `node_modules/`, `training/data/`.

## Definition of done
Tests green · no new knowledge in code · new facts in the ledger and covered by the verifier · new sources in README +
CONNECTIONS.md · MEMORY.md updated (Progress, Decisions, Findings, Session log).

## Adding an activity
1. Add it to `knowledge/activities.yaml` (label, synonyms, `nominatim_phrases`, venue selectors, comfort, limits,
   weights summing to 1, special flags). The intent enum updates automatically.
2. Advice items in `knowledge/advice.yaml` if it needs specific gear/risks.
3. Add ≥3 queries to `backend/eval/queries.jsonl` and regenerate the training data in Colab.
